# Handler Layer Summary — Unit 9: API Gateway

## `src/handlers/proxyHandler.js`
Factory `proxyHandler(client, serviceName)` returning an Express handler. Forwards method/headers (including `X-Request-ID`, generated by `middleware/correlation.js` if absent)/body/query to the injected `httpClient`, and mirrors the downstream response (status + body, including 3xx `Location` for the OAuth redirect flow) back verbatim — no re-validation or transformation (interface-contracts.md "Passthrough Behavior"). On `UpstreamUnavailableError` (connection failure or 30s timeout from `httpClient`), returns `502 {error: "upstream_unavailable", service: serviceName}`. Used by `routes/plugins.js`, `routes/sagas.js`, `routes/projects.js`, `routes/auth.js`.

## `src/handlers/progressHandler.js`
Factory `progressHandler(amqpClient)` returning `{ subscribe, dispatch }`. `subscribe` is the Express handler for `GET /v1/progress/:id` — validates/sanitizes the `project_id` path param (minimal sanitization only, per NFR Design's explicit boundary), sets SSE headers, registers the response in an in-memory `Map<projectId, Response[]>`, and removes it on `req.on('close')`. `dispatch` is called by the AMQP consumer (wired in `server.js`) for every `progress.fanout` delivery; it looks up subscribers for the message's `project_id` and writes `data: <json>\n\n` to each. If no one is subscribed, the message is dropped silently (at-most-once, no replay buffer — messaging-design.md). The AMQP message is acked by `amqpClient` regardless of whether the SSE write succeeds.

## Testing
`tests/handlers/proxyHandler.test.js` uses a fake client object (`{ request: jest.fn() }`) and fake Express `res` stub to verify passthrough of success/error responses, redirect forwarding, X-Request-ID propagation, and the 502 mapping. `tests/handlers/progressHandler.test.js` uses fake request/response objects to verify subscribe/dispatch/cleanup-on-close and the silent-drop and invalid-project-id-rejection behaviors.
